# 前端菜单合并优化 — 需求文档

## 问题

当前前端侧边栏菜单包含 **13个菜单项** 分4组，功能重叠严重：

| 重叠类型 | 涉及页面 | 具体重叠 |
|---------|---------|---------|
| 模型启停/切换 | Dashboard, ModelManagement, GPUManage, EngineManagement | 4个页面都能启停/切换模型 |
| GPU数据展示 | Dashboard, MonitorView, GPUManage | GPU指标图表重复渲染 |
| 引擎配置 | ConfigManagement, EngineManagement | 2个页面都可编辑引擎配置 |
| 健康状态 | Dashboard, HealthOpsPage | 健康告警卡片重复显示 |
| 登录入口 | Sidebar菜单 | 已登录用户不需要看到登录菜单项 |

用户面对13个选项不知所措，操作路径混乱。

## 合并方案

### 现有结构 → 目标结构

```
核心控制(6)                    →  核心控制(2)
  总览面板                       总览面板
  模型调度                       模型中心 ← 合并调度+搜索+池+评测为Tab
  模型搜索
  模型池
  模型评测
  AI Agent                    →  工具(2)
                                 AI Agent
数据监控(3)                    →  监控运维(2)
  实时性能                       GPU监控 ← 合并性能+GPU管理为Tab
  GPU管理
  系统文档                    →  工具(2)
                                 系统文档
系统管理(4)                    →  监控运维(2)
  引擎管理                       系统运维 ← 合并引擎+限流+配置+健康为Tab
  限流控制
  配置中心
  健康运维
安全(1)                        →  移除
  安全鉴权                       (登录通过路由守卫自动跳转)
```

### 最终菜单: 3组6项

| 组 | 菜单项 | 说明 |
|---|--------|------|
| 核心控制 | 总览面板 | Dashboard，仅展示状态，去掉启停操作 |
| 核心控制 | 模型中心 | 4个Tab: 调度/搜索/池/评测 |
| 监控运维 | GPU监控 | 2个Tab: 实时性能/GPU管理 |
| 监控运维 | 系统运维 | 4个Tab: 引擎/限流/配置/健康 |
| 工具 | AI Agent | 对话界面(不变) |
| 工具 | 系统文档 | 文档浏览(不变) |

## 验收标准

1. 菜单项从13个减少到6个，每组不超过2项
2. 模型中心页面包含4个Tab(调度/搜索/池/评测)，保留原有核心功能
3. GPU监控页面包含2个Tab(实时性能/GPU管理)，保留原有功能
4. 系统运维页面包含4个Tab(引擎/限流/配置/健康)，保留原有功能
5. Dashboard去掉模型启停操作按钮，只保留状态展示+引导链接
6. 移除侧边栏"安全鉴权"菜单项
7. 所有原有路由仍然可用(redirect到合并后新路由)
8. Tab切换流畅，不重新加载组件
9. TypeScript编译和pnpm build通过
