## 需求范围
基于 PRD 功能点 14-22，对 Vue3 前端进行重新设计升级迭代。重点：
1. **F14: 多引擎支持** — vLLM/SGLang/llama.cpp 动态切换
2. **F15: 多源模型下载** — HF/ModelScope/OpenXLab + WS进度 + 断点续传
3. **F16: 跨平台模型搜索** — 关键词搜索+显存估算+可行性标注
4. **F17: GPU显存智能优选** — 实时检测+推荐最优+一键下载加载
5. **F18: 模型池统一管理** — 搜索下载入库+一键加载+状态校验
6. **F19: Dashboard仪表盘** — GPU/模型/系统一站式概览
7. **F20: 模型管理页** — 启停/切换/预加载/引擎选择
8. **F21: GPU监控详情** — 实时指标+历史趋势+进程列表
9. **F22: Agent对话页** — 多会话+流式+工具调用可视化

## 意图树

### 核心意图
- **业务目标**: 将分散的模型搜索/下载/引擎/显存/模型池功能整合到统一前端管控面板，实现搜索→下载→校验→加载→推理的全流程可视化
- **用户**: 管理员/运维人员
- **痛点**: 当前前端功能碎片化，引擎切换信息不直观，下载进度缺乏实时性，显存信息不够醒目

## 验收标准 (Given/When/Then)

### AC-1: 多引擎切换
- Given: 至少一个引擎(vLLM)正在运行模型
- When: 管理员在引擎面板点击切换到SGLang引擎
- Then: 显示4阶段进度(含Phase2.5显存校验)，完成后SGLang引擎运行原模型

### AC-2: 模型搜索下载
- Given: GPU可用显存>0且后端服务正常运行
- When: 管理员输入关键词并选择搜索源
- Then: 返回搜索结果列表含显存可行性徽章，下载时显示WS实时进度

### AC-3: 显存优选推荐
- Given: GPU可用显存已知且搜索结果>0
- When: 管理员点击"显存优选"按钮
- Then: 系统筛选可运行模型并推荐最优，显示推荐模型+GPU信息+候选列表

### AC-4: 模型池一键加载
- Given: 模型池有可用模型且GPU显存足够
- When: 管理员选择模型并点击"一键加载"
- Then: 系统执行显存校验→引擎启动→就绪验证，成功后模型运行

### AC-5: Dashboard GPU告警
- Given: GPU利用率>85%
- When: 管理员查看Dashboard
- Then: GPU可用显存显示红色告警标识，可用显存数值醒目

### AC-6: 模型调度引擎面板
- Given: 多引擎后端服务可用
- When: 管理员访问模型管理页面
- Then: 显示当前引擎状态+切换面板+Phase2.5显存校验步骤

## 隐含需求

### 基于场景的强制推断
- **场景: 模型下载中断** → 需断点续传UI提示(显示已下载百分比+续传按钮)
- **场景: GPU显存不足** → 需拒绝加载+告警+建议可运行模型列表
- **场景: WS连接断开** → 需降级到轮询+状态指示灯切换
- **场景: 后端不可用** → 引擎面板/搜索/下载优雅降级(空状态+错误提示)
- **场景: 多下载并行** → 需下载队列管理UI

## 边界条件
- **做什么**: 前端UI重新设计和功能升级(不涉及后端代码改动)
- **不做什么**: 不改Go后端代码、不改Python后端核心逻辑、不改aiclient2api插件
- **边界**: 前端页面路由/composable/API client层可改，但API端点保持兼容

## 接口依赖
所有前端所需API已在 `api/client.ts` 中定义：
- `getEngineStatus()` / `switchEngine()` — 引擎管理
- `searchModels()` / `recommendModel()` / `checkModelMemory()` — 搜索+显存
- `startDownload()` / `getDownloadStatus()` / `cancelDownload()` / `listDownloads()` — 下载
- `getPoolList()` / `loadFromPool()` / `deleteFromPool()` — 模型池
- `getGPUSummary()` / `getGPUHistory()` / `getGPUMemoryCheck()` — GPU监控
